# Scope every element id to its instance, and write the rule down

Elements in this crate minted `ElementId`s that were unique only within one instance of themselves — `div().id("textarea")` is the same id for every textarea on screen. gpui keys element state on an element's *whole* id path and hashes that same path into an AccessKit node id, where a duplicate trips a `debug_assert!` in debug builds and is silently dropped from the a11y tree in release. Nothing crashed today only because none of these elements reports a role, and a node needs *both* an id and a role to reach the tree — the same latent state markdown was in before #126. This change audits every `.id(...)` in `src/` and adds `src/element_id.rs`: the rule stated once, the two helpers that implement it (`for_entity(name, entity_id)` for an element backed by an entity, `scoped(&parent_id, part)` for a named part of one), and — the part that is easy to get wrong — what does and does not scope an id in gpui, since an `Entity<V: Render>` child pushes an id segment while a `RenderOnce` struct, a bare `div()`, and `deferred()`/`anchored()` do not. Three of the five elements the issue named turned out not to collide at all (they sit under an ancestor that scopes them), and one it did not name — the context menu popup — does; the audit walked the ancestor chain rather than taking the list at face value.

Three genuine collisions are fixed, each with a named, unit-tested id-minting function next to the element so the id is checkable without drawing a frame: the alert dismiss button (`dismiss_element_id`), the textarea (`textarea_element_id`, plus `Textarea::id`/`::element_id` mirroring `MarkdownElement` for the one case an entity cannot separate — one `InputState` rendered by two textareas), and the context menu popup (`menu_element_id`, now passed into `menu_popup`). Seven more sites that were unique only by accident of an ancestor they do not control now derive their own — the dropdown menu, popover panel and toast container from their backing entity; the dialog panel and close button, the toast action and dismiss buttons, and the slider track from their instance's id — each with a one-line comment saying what it used to lean on. `element_id::tests::no_element_mints_a_constant_id` scans every `.rs` under `src/` and fails with file:line on any element minting a constant id, skipping top-level `#[cfg(test)]` modules because a *caller* passing `.id("left")` to an override API is correct usage. No API is removed; the only additions are the `element_id` module and `Textarea::id`/`::element_id`. Roles are deliberately still absent from all ten elements — ids first, roles second; adding them is now the one-line change it looks like rather than a process abort.

Verification: PASSED — `cargo test --all-features --lib` (402 passed, 0 failed), plus `cargo check --all-features --all-targets`, `cargo clippy --all-features --all-targets` (75 warnings, byte-identical to the pre-change tree), `cargo fmt --all --check`, and `cargo doc --all-features --no-deps` (4 warnings, all pre-existing). The guard test was also confirmed to fail as intended by temporarily reverting one of the fixed ids. `cargo test --all-features` without `--lib` is not runnable in this environment — I tried it, and `ld` was killed by signal 9 (out of memory) linking an example binary (`examples/context_menu`) before any test could run. That is an environment limit, not a code problem: the same targets pass `cargo check --all-features --all-targets`.
